```
O problema que me fez construir um produto

Ferramentas de gestão de projetos prometem organizar o trabalho — mas,
na prática, muitas se tornam parte do problema. Cliques demais para ações
simples, alternância constante entre mouse e teclado, e interfaces que
competem com o trabalho real pela atenção do usuário.

O Aero é minha resposta: um ecossistema de gestão keyboard-first, criado
para reduzir a fricção entre ideia, documentação e execução. Este case
reconstrói retrospectivamente as decisões que orientaram sua criação —
sem inventar pesquisas que não aconteceram.

Projeto solo · Estratégia, UX/UI, Prototipação e Front-end · 2–3 meses
```

### ✏️ Módulo 5 — Texto
```
Três princípios, um produto

Em vez de começar pelas telas, comecei por hipóteses de comportamento:

01 — Fricção zero: registrar uma ideia deve ser quase instantâneo.
02 — Densidade útil: mais contexto por tela, sem ruído decorativo.
03 — Keyboard-first: atalhos e comandos tornam o mouse uma escolha, não uma obrigação.

Cada decisão de interface que se segue responde a pelo menos um desses princípios.
```

### ✏️ Módulo 8 — Texto
```
Decisão de UX 01 — Command Menu

Em vez de percorrer menus e submenus, o usuário salta diretamente para
uma ação ou destino com CMD/CTRL + K. O command menu centraliza comandos,
reduz deslocamentos e — mais importante — mantém o ritmo de quem está
pensando e executando ao mesmo tempo.
```

### 📷 Módulo 9 — Imagem `06-06-drawer.png`
*(Decisão de UX 02: drawer lateral preserva contexto)*

### ✏️ Módulo 10 — Texto
```
Decisão de UX 02 — Drawer, não página

Abrir uma tarefa em página nova interrompe o fluxo: o usuário perde de vista
o quadro, o sprint e os gargalos. No Aero, o detalhe abre em um drawer lateral
que mantém tarefa e contexto visíveis ao mesmo tempo. Editar a especificação
sem abandonar a visão do todo.
```

### 📷 Módulo 11 — Imagem `07-07-design-system.png`

### ✏️ Módulo 12 — Texto
```
Design system — cor como sinal, não decoração

Uma base neutra (#101115 / #24262F) elimina competição visual. A cor só
aparece quando comunica: azul (#388CFA) para ação, magenta (#911756) para
destruição, verde/roxo para estados. Tipografia funcional em duas famílias —
Inter para conteúdo, JetBrains Mono para metadados e status.

O resultado: uma interface que some durante o uso e só "fala" quando
tem algo importante a dizer.
```

## 4. Por que esta estrutura funciona para recrutadores

1. **Hook visual imediato** — capa com mockup escuro de alto contraste se destaca no feed
2. **Honestidade como diferencial** — "retrospective case" sinaliza maturidade; recrutadores detectam personas falsas
3. **Decisões, não telas** — cada seção responde "por quê", não só "o quê"
4. **Full-stack de design** — estratégia + UI + código mostra autonomia completa
5. **CTA duplo** — produto ao vivo (prova) + contato direto (conversão)
